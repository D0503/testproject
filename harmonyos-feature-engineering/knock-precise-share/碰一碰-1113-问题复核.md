## 原报告自身需要修正的地方

1. **结论与门禁自相矛盾**：页首是“证据不足 / insufficient_evidence”，摘要末尾却是“基本合格但需修改 / pass_with_warnings”。应由最终保留问题和关键待核项重新计算，不能同时保留两套结论。
2. **26项摘要与14项可见正文不一致**：被注释的条目仍进入总数、结构摘要和维度扣分说明。HTML注释不等于完成了撤回与重新评分。
3. **原报告的证据引用无法独立回查**：提供的 Markdown 只有 EVID 编号，未附完整证据表、哈希、原始快照或对应 JSON。因此本次以已取得的同日官网原文及 SDK 重新判断，不把编号本身当证明。
4. **过度泛化的核验结论**：“两篇API全部签名、枚举、错误码、@since与SDK一致”不能仅凭若干SDK-CC编号确认；尤其 SDK 没有描述的设备行为、运行错误和裁剪机制不能算已验证。
5. **待核项不得继续扣分**：receive路径兼容、windowId重载行为、Beta4覆盖和坐标辅助类未取得证据，不应只换成 likely/ambiguous 就正式扣分。建议移入待核后重新生成九维分数；不能沿用81分作为复核后的分数。
6. **建议改写不能发明规范**：DOC-005 的 Beta4起限制、DOC-011 的 3:4端点、DOC-013 的同包名优先顺序和 DOC-020 的至少401都缺证据，不能直接提供给维护者作为正确答案。
